# P0-12D2A — selected-catalog identity and browser-session isolation

Baseline: `0ae5cc0c1a705344cbae103bfba6a79e4b0293ec` (PR #82 merged into draft PR #72).

## Implementation

- Room `OpdsDao.getFeedById` uses the selected row's primary key, without a schema change. A browser opening gets an `OpdsCatalogSession` with the selected ID and original URL. A process-memory-only salted stamp of nullable credential fields and generation is used to reject stale edits without retaining a second plaintext pair. This is not password hashing for storage or a persistent authentication token.
- The scoped network path loads only the selected ID, requires the same URL and credential revision, and sends the legacy Basic credentials only to the exact approved HTTPS origin. Missing, changed, invalid or incomplete same-origin selections fail closed. Foreign-origin downloads remain anonymous. A non-null encrypted-generation marker is not interpreted as anonymous or as permission to use legacy fields on the same origin. Encrypted generations are not activated by this slice.
- Each browser opening has an independent in-memory cookie jar. Cookie reuse requires the exact HTTPS origin, unexpired cookie, and OkHttp path/domain/secure matching. The scoped network interceptor strips Authorization and Cookie headers on foreign-origin network requests, including redirect follow-ups. HTTPS-to-HTTP redirects remain disabled. The session-keyed client cache does not retain the session object in its values. The legacy URL-only compatibility APIs and their original cookie behavior remain for existing tests/callers until D2B removes or restricts that path.
- The Leisure catalog browser carries the selected session through folder navigation, pagination, breadcrumb navigation, book and cover downloads; Gutendex remains on its existing separate repository path. Delayed responses and queued stale item clicks cannot overwrite a new browser selection. A download already started can finish using its original captured selection; it does not switch to the new catalog's credentials. Credential edits require reopening the browser for further scoped requests. This does not cancel already-issued network requests and does not serialize CRUD with network dispatch yet.
- Scoped request failures avoid reporting raw endpoint/backend/response error details. Existing URL-only compatibility behavior remains otherwise unchanged. No Books/Comics reader, dependency, schema, iOS, signing, or encryption-policy changes.

## Tests and limits

Eight isolated Kotlin session-policy tests were executed with the current OpdsEntity and OpdsCredentialStorage source, verified against GitHub blob IDs. Only the Room/JUnit annotations are stubbed for that isolated runner; coroutine and JDK implementations are real. New project tests also cover cookie isolation (3), repository routing (2), and browser session handling (2). These seven additional tests and the full Android build require the project's actual Gradle dependencies; they were not run in the package environment. The intercepted request test verifies initial request headers; it does not exercise real network redirects or TLS. Verify same-/cross-origin redirects and cookie behavior on a disposable emulator/test endpoint before security acceptance.

## Remaining gates (do not close SEC-03)

Production CRUD still writes legacy plaintext credentials and the old URL-only compatibility path still exists. D2B/E must integrate authenticated generation reads/writes, journal-aware mutations, safe retirement/reconciliation, explicit Keep/Replace/Remove editing, serialized migration, and removal/restriction of the compatibility path before migration activation. Review all production call sites and Gutendex routing; verify stale credential edits and interrupted operations. Historical SQLite/WAL/backup remanence and real Android filesystem, TLS and Keystore acceptance remain open. Do not install over personal data or downgrade a v4 database. PR #72 remains draft until all security acceptance conditions are satisfied.
