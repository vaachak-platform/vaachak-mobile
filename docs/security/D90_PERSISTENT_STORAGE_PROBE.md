# D90 persistent AI storage — policy probe (review candidate)

Status: **not connected to the live application**. ADR-01 product policy approved; API-specific implementation and security review pending. All release acceptance remains pending.

## Candidate implementation

- VAI3 ciphertext and a distinct per-vault/provider Android Keystore AES-256-GCM alias; randomized IV, authenticated slot/vault binding, no-backup storage, bounded envelope, pre-publication cryptographic verification and durable atomic publication using the existing `DurableCredentialFile`. Read-back verified after publication. A post-rename failure can leave new ciphertext present; live migration must account for that state. No legacy VAG1/VAG2/VAS2/OPDS file or alias is opened, changed or retired by this backend.
- Key explicitly requires an unlocked device, not recent per-use/timed user authentication. No fallback to a key without unlocked-device enforcement. API 30 encryption operation restrictions differ from decryption; application additionally requires secure lock, first user unlock, interactive/unlocked device and caller-supplied foreground eligibility. Android 12–14 documented unlocked-key bugs may block use or cause key loss after lock removal. No device compatibility guarantee until tested. Fail closed on missing/unusable key. See the Android `setUnlockedDeviceRequired` documentation and D90-ADR-01. Key hardware backing is not assumed.
- `AiManagementGrantLedger` models one-use challenges/grants bound to vault, slot, operation, revision and host epoch. Prompt challenge expires after two minutes; management grant expires after 30 seconds. These limits apply only to an explicit management operation, never routine reading. It is **not an authentication implementation**; the native prompt coordinator must be the only authority that completes a challenge, revalidate the persisted context and revoke on lifecycle changes. No secret is held in the ledger.
- Existing SettingsRepository and runtime AI paths are unchanged, including old PIN-only v2 behavior. No live credential migration, explicit deletion/tombstones, provider UI, native prompt or request cancellation is added in this slice. These are blockers, not optional deferrals. No production use of the candidate backend until all such boundaries are connected and verified. No shared key-policy changes or quality/security gate changes.

## Evidence

Standalone Kotlin harness executed the actual 11 pure grant test bodies (JUnit annotation stub only; not Gradle or Android testing). Run the normal Core and Leisure unit suites on the user's machine. Synthetic Android policy probe tests are supplied separately for a targeted run, since a timed test in the existing shared-key suite could expire legacy v2 authorization. They do not use any real provider credentials, change PIN settings, delete existing aliases or change app data; they create and retire only a randomly named test vault's VAI3 files/aliases. They are not a replacement for consolidated instrumentation. Do not mark any acceptance PASS from this probe alone.

Device probe cases: new key persists beyond 65 seconds with a fresh storage instance, no plaintext in envelope, randomized encryption, AES-256, no recurring-auth requirement; foreground eligibility, independent slots and tampered ciphertext; missing alias does not regenerate or overwrite ciphertext. Synthetic foreground flag does not prove real Activity lifecycle enforcement. Native prompt, actual lock/unlock/lock removal, reboot, >15 minutes, process death, upgrade, downgrade, real vault transitions, sync/OPDS regression, and source/hotspot review remain unqualified.
