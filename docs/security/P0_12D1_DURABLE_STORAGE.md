# P0-12D1 — authenticated ciphertext durability

Base: b7ca98f50f49ace18e7fd94dafdc19e9cbb1cf7d (PR #81 merged into draft PR #72).

Atomic rename provides atomic visibility, not a durability guarantee after abrupt power loss. Before OPDS migration may clear legacy fields, the encrypted generation must survive a successful file-data and directory-metadata sync. The shared PrivateGatewaySecrets writer now writes ciphertext to a same-directory temporary file, synchronizes its file descriptor, atomically renames it, then synchronizes the directory using Android Os. No non-atomic fallback. A failure propagates; after rename the new ciphertext may already exist. Do not infer that the old ciphertext still exists or automatically delete the replacement.

The OPDS backend adds an explicit durability barrier for a retry of an identical generation. It opens an existing file without CREATE, forces it, syncs the directory, and verifies read-back. An unavailable barrier is not success. No credential may be published on an unsuccessful write or barrier. Existing immutable generation and origin checks remain. Hilt singleton scope plus a process-wide key-creation lock serialize key creation in the application process. This is not interprocess coordination. Do not activate migration in a multiprocess configuration without a separate review.

AES-GCM format, AAD, aliases, authentication policy, noBackupFilesDir, read/clear behavior and legacy migration format are unchanged. All providers sharing this writer receive the stricter durability check; device/filesystem support and regressions must be tested. The change does not claim physical power-loss immunity or forensic plaintext erasure. The underlying filesystem/storage must honor synchronization. No new credential activation, Room schema change, cleanup of retired files, catalog CRUD/UI change, or network change is introduced.

Local package verification: 31 isolated JVM tests (storage, migration, filesystem helper) executed with real temporary files and injected directory-barrier failure. These do not execute Android Os, Android Keystore, Hilt, Room, or a power interruption. Run full Gradle checks and real PIN-authenticated emulator tests before accepting the shared writer for production. Do not install over personal data. P0-12D2 (repository and catalog identity wiring), P0-12E (editor), and P0-12F (device/upgrade acceptance) remain open. Keep PR #72 draft.
