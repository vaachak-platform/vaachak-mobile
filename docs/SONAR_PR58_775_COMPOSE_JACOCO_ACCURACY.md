# PR #58 — Correct Compose coverage accounting and identify remaining branches

## Observed problem

SonarCloud's latest new-code coverage was **77.5%**. `SettingsScreen.kt` moved from 146 uncovered conditions to 143 after a test matrix with more than 300 input scenarios. The small gain is evidence that adding more scenarios without examining missed source lines is inefficient. It does not prove every remaining branch is compiler generated.

The reconstructed project still pinned JaCoCo **0.8.12**, predating JaCoCo **0.8.13**'s official filtering of part of the Kotlin Compose compiler-generated bytecode. Gradle/JVM JaCoCo and Android Gradle Plugin's instrumented-test JaCoCo version are independently configured. This package aligns both in `core` and `leisure` to published **0.8.16**, without excluding files, hiding tests, changing production code, or lowering Sonar quality gates.

Sources:
- https://www.eclemma.org/jacoco/trunk/doc/changes.html (0.8.13 Kotlin Compose filtering, with later improvements)
- https://developer.android.com/studio/test/coverage-report (Android `testCoverage.jacocoVersion`)

## Expected changes

- `gradle/libs.versions.toml`: `jacoco = "0.8.16"`.
- `core/build.gradle.kts`: Gradle `jacoco.toolVersion` and Android `testCoverage.jacocoVersion`.
- `leisure/build.gradle.kts`: existing `jacoco.toolVersion` retained; new `testCoverage.jacocoVersion`.

## Validation on your Mac

Review complete-file replacements against current checkout first. The package uses the most recent reconstructed source archive available in the conversation, not live GitHub.

```sh
./gradlew :core:testDebugUnitTest :core:jacocoDebugUnitTestReport :leisure:testDebugUnitTest :leisure:jacocoDebugUnitTestReport :leisure:assembleDebugAndroidTest
./gradlew :core:createDebugAndroidTestCoverageReport :leisure:createDebugAndroidTestCoverageReport
```

Run the *full suite*. Do not reuse stale reports produced using JaCoCo 0.8.12.

For per-line missed-branch counts, inspect:

`leisure/build/reports/coverage/androidTest/debug/connected/report.xml`

Each `sourcefile name="SettingsScreen.kt"` element contains `<line nr="..." mb="..." cb="..."/>`. `mb` = missed branch outcomes, `cb` = covered branch outcomes.

Run this read-only command to identify the 30 source lines with the most missed outcomes:

```sh
python3 - <<'PY'
import xml.etree.ElementTree as ET
from pathlib import Path
p = Path('leisure/build/reports/coverage/androidTest/debug/connected/report.xml')
r = ET.parse(p).getroot()
for pkg in r.findall('package'):
    for src in pkg.findall('sourcefile'):
        if src.get('name') == 'SettingsScreen.kt':
            print('source:', pkg.get('name') + '/' + src.get('name'))
            lines = [(int(x.get('mb','0')), int(x.get('cb','0')), int(x.get('nr'))) for x in src.findall('line')]
            for mb,cb,nr in sorted(lines, reverse=True)[:30]:
                if mb:
                    print(f'line {nr:>4}: {mb} missed / {cb} covered outcomes')
PY
```

## Interpretation

- If missed branch counts drop: this corrects reporting of compiler-generated bytecode, which is a measurement accuracy improvement, not additional test execution.
- If missed counts remain high: use the top source-line numbers for **targeted tests**, not more theme/comic cross-products. Both numerator and denominator can change after the version upgrade.
- Sonar's **new-code coverage** and local JaCoCo full-file coverage are not identical. Only the next PR scan confirms the actual gate result.
- Do not change Keystore authentication, quality-gate thresholds, coverage imports, source exclusions, or BOOX compatibility policies to make the number move.
